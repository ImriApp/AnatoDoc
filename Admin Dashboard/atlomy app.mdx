## Configurations

Configurations keep ATLOMY.com up to date. They import updated versions of our tables in [Greek Lexicon DB](../Greek%20Lexicon%20DB/greek%20lexicon%20db.mdx) into the admin dashboard's own database. Lemma pages are created, deleted, and modified as part of this process.

Formerly, updating ATLOMY.com required manually exporting the Lemma Pool as a CSV file. It would be saved on AWS S3, to which the dashboard would connect for importing its data. Nowadays, an API allows direct connection from the dashboard to our workspace on Coda, making the configuration process quicker and more comprehensive.

### To run a configuration

1. Make sure that all rows in the **Lemma Pool** are attributed a properly formatted name, translation, and transliteration. This is crucial for the configuration to run successfully.
2. On the dashboard, enter **ATLOMY App > Configurations > Run script**.
3. For **Content**, you can change the dates in the script to achieve a faster configuration time. By default, the script is set to update all rows in the Lemma Pool that were created since Februery 15, 2021, and all rows in the lemma pool modified since April 27, 2021. You can change these dates to more recent ones, so that only rows created or modified after them will be imported to the dashboard.
4. For **Use Coda**, make sure “yes” is selected.
5. For **Status**, change “stopped” to “running.”
6. Click **Save**.

After clicking save, the add_data script is run, which includes these steps:

1. Elastic is updates with the additions, deletions, and changes in Greek Lexicon DB.
2. All lemmas entries in Elastic are compared with the lemma pages in the dashboard.
3. Based on this comparison:
    - Lemma entries in Elastic that do not have a corresponding page in the dashboard are copied to the dashboard from Elastic.
    - Lemma entries in Elastic that have a corresponding page in the dashboard are updated to match Elastic.
    - Lemma entries in Elastic that were marked for deletion in the lemma pool prior to running the configuration are de-activated on the dashboard, and they will not appear in search results nor in responses from the Lemmas API.

ATLOMY.com will be fully updated within 10-15 minutes of clicking save.

Once a configuration is finished, its status automatically returns from “running” to “stopped”.

## Feedbacks

Feedbacks entered by ATLOMY's users go into this inbox. Each item in this list contains the user's email address, their institute (if entered by them), the content of their feedback, and checkmarks for following up on their query.

## Jobs

Jobs are JSON files created automatically in the admin dashboard after each configuration. They report on the successes, warnings of failure, or failures in the configuration process.

Warnings of failure are common. They stem from lemmas in the Lemma Pool not being attributed fully, for example, when they lack short or long descriptions, or a list of references. Failures, on the other hand, stem specifically from the lack of a lemma's name, translation, or transliteration (read further on metadata in the Coda Guide).

## Lemmas

**Configurations** import all lemmas in the Lemma Pool into the dashboard, creating a corresponding list of **lemma pages** in this section. Currently, lemma pages cannot be created manually on the dashboard, but only imported.

Since textual data imported to the dashboard is imported in plain text, and since lemmas’ **short and long descriptions** need be formatted in rich text (with bolds, italics, underlines, colors, etc.), this section is mainly used for reformatting them, using the text editor.

The **Is Active** field of each lemma is linked to the **Marked for Deletion** field on the Lemma pool. When checking the box under Marked for deletion for one of the items in the lemma pool, running a configuration will result in de-activation of that lemma on the dashboard. Such a lemma will not appear in search results nor in responses from the Lemmas API.

Note: lemma pages which were created manually in the admin dashboard, and are then created separately as a row in the Lemma Pool, will be updated rather than get duplicated when running a configuration. However, creating or editing lemma pages directly through the dashboard is strongly discouraged, the short and long description fields being the only exception. Deleting a lemma page will break any reference to its lemma. This includes URLs, model lemmas, and search results, which will no longer function or return results. (For more on creating and updating lemma items, read on Configurations).

## Model lemmas

This section lists connections between models and lemmas - each row is a single connection between a lemma page and a model page, reflecting the list of connections in **Modelling Instructions Sub-Items** in **Coda > Visualization**.

These connections are shown both on model pages - when looking into a body part - and lemma pages - in the list of relevant models.

### To connect a model page to a lemma page:

1. On the dashboard, enter **Model Lemmas**.
2. Click **Add Model Lemma** on the upper right corner.
3. Select the **model page** and the **lemma page** that you want to connect.
4. Click **Save**.

The connection of the lemma to its specific body part occurs automatically afterwards, as the 3D Object is already named the same by the 3D modeler.

## Models

Model pages contain 3D models and model information, and they are created and managed in this section.

Initially, 3D models and model thumbnails were uploaded to the admin dashboard. Nowadays, they are stored on **AWS S3**, from which they are retrieved when browsing ATLOMY and entering a model page.

To create a new model page:

1. On the dashboard, enter **Atlomy App > Models**.
2. Click on **Add model** on the upper right corner.
3. Then enter:
    * **Model Name**, following the formula ”[ancient author] - [system name]” (e.g. “Galen - Hindlimb”)
    * **URL** for the 3D model stored on AWS S3
    * **URL**s for the thumbnails stored on AWS S3. There are three thumbnail sizes - one for the home page (168x140px), one for a detailed view (246x180px), and one for search (50x30px).
    * The model's **Description** as it was written by the philologist
    * The **Ancient Author**'s name
    * Zoom ration and position
    * The **Author**'s name (i.e. the philologist, not the ancient author)
4. Choose whether the model is ready for featuring in ATLOMY's home page.
5. Click **Save**.

## Pages

As **Lemma Pages** and **Model Pages** are managed in their own sections, this section manages all other types of pages:

* **Author Pages** show information about Aristotle, Galen, Hippocrates, and Celsus, and they are accessed through the 
reference list in any lemma page.
* **Treatise Pages** show information about treatises, such as Hippocrates' On the Heart and Aristotle's History of Animals, and they are accessed through the reference list in any lemma page.
* **Other Pages** are independent of lemma information and are accessed through the home page. Examples are the **How to use ATLOMY** and **About** pages.
